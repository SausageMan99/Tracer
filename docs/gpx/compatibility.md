# GPX Compatibility

Reference for the GPX 1.1 export format and device/app compatibility requirements.

---

## Overview

`lib/gpx-export.ts` generates GPX 1.1 files from route candidates. GPX (GPS Exchange Format) is the de facto standard for importing routes into cycling computers, running watches, and navigation apps.

The implementation prioritises compatibility with the most popular GPS devices over spec minimalism — several fields that are technically optional are included because major devices reject files that omit them.

---

## GPX 1.1 Structure

```xml
<?xml version="1.0" encoding="UTF-8"?>
<gpx
  version="1.1"
  creator="TrailForge"
  xmlns="http://www.topografix.com/GPX/1/1"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:schemaLocation="http://www.topografix.com/GPX/1/1
                      http://www.topografix.com/GPX/1/1/gpx.xsd"
>
  <metadata>
    <name>TrailForge — Adresse de départ (15.2 km, D+480m)</name>
    <time>2024-11-15T14:32:01.000Z</time>
  </metadata>

  <trk>
    <name>TrailForge — Adresse de départ (15.2 km, D+480m)</name>
    <trkseg>
      <trkpt lat="45.7640" lon="4.8357">
        <ele>168.0</ele>
        <time>2024-11-15T14:32:01.000Z</time>
      </trkpt>
      <!-- ... more points ... -->
    </trkseg>
  </trk>
</gpx>
```

## Required Fields by Device

Many GPS devices implement a subset of the GPX 1.1 spec and require specific fields that the spec marks as optional.

| Field | GPX spec | Required by |
|-------|----------|-------------|
| `<ele>` on every `<trkpt>` | Optional | Garmin Edge, Wahoo ELEMNT, Suunto |
| `<time>` on every `<trkpt>` | Optional | Wahoo ELEMNT, Garmin Connect import |
| `xsi:schemaLocation` | Optional | Suunto Movescount |
| `<metadata><time>` | Optional | Garmin Connect (sorts imports by date) |
| UTF-8 encoding declaration | Optional | Suunto (rejects non-declared encoding) |

### Why `<ele>` is required

Garmin Edge devices use `<ele>` to display a live elevation profile on-device during navigation. Without it, the device may:
- Import the route successfully but show a flat elevation profile
- On some Edge models (1030, 1040), refuse to import the file entirely

TrailForge always includes `<ele>` if elevation data is available. Points with `elevation: undefined` (which can occur if the Open-Meteo API returned null for that coordinate) use `0` as a fallback.

### Why `<time>` is required

Wahoo ELEMNT requires timestamps on every track point to import a GPX file as a "workout" (as opposed to just a route). Without timestamps, the file imports as a course but power/pace analysis is unavailable. Garmin Connect also uses timestamps for import ordering.

Since TrailForge generates future routes (not recorded tracks), the timestamps are synthetic. See the Synthetic Timestamps section below.

## Synthetic Timestamps

Routes generated by TrailForge have no real recording timestamps. The export generates synthetic ones to satisfy device parsers.

**Strategy:**

```
startTime = export timestamp (moment the user clicks "Export GPX")
totalDuration = best.durationSeconds
intervalSeconds = totalDuration / (points.length - 1)

for each point i:
    time[i] = startTime + i × intervalSeconds
```

The result is a time series starting now, with points evenly spaced by the estimated duration. This is a plausible but entirely synthetic recording.

**Why not use real time?** The route has not been run/ridden yet. There is no meaningful real time to use. Devices do not validate that timestamps are in the past.

**Why evenly spaced?** Uneven spacing (accounting for speed variation by gradient) would be more realistic but adds complexity with no practical benefit — device parsers use timestamps for total duration calculation, not per-segment speed. Even spacing produces a correct total duration.

## XML Character Escaping

Route names are derived from the user's address input, which may contain arbitrary Unicode characters. The `escapeXml()` function escapes the five XML-special characters before including them in attribute values and element text:

| Character | Escaped |
|-----------|---------|
| `&` | `&amp;` |
| `<` | `&lt;` |
| `>` | `&gt;` |
| `"` | `&quot;` |
| `'` | `&apos;` |

**Example:**

```
Address: "Rue de l'Église & la Forêt"
GPX name: "TrailForge — Rue de l&apos;Église &amp; la Forêt (12.3 km, D+280m)"
```

## File Naming

The exported filename is generated from the route metadata:

```
TrailForge-{date}-{distanceKm}km.gpx
```

**Example:** `TrailForge-2024-11-15-15.2km.gpx`

The date uses ISO format (YYYY-MM-DD) for consistent alphabetical sorting in file managers.

## Limitations

### No waypoints in GPX export

The current export includes only the main track (`<trk>`). Optional waypoints (`<wpt>`) for start/end markers or intermediate points are not included, as most GPS devices place start/end markers automatically at the first and last track points.

### No route type metadata

GPX 1.1 supports a `<type>` element for categorising activities. TrailForge does not include this because the valid values vary by app (Garmin uses `"running"`, Strava uses `"Run"`, etc.). Devices default to the appropriate type based on the device profile.

### Maximum file size

A 500-point route generates a GPX file of approximately 40–60 KB. All tested devices and apps handle files up to 10 MB without issue, so file size is not a practical concern.
